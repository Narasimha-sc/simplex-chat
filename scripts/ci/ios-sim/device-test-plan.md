# Device test plan: SimpleX names, a directory group with captcha, and a pending link moved to another profile (checklist batch B15)

## Anything unusual

You are looking for regressions, not only running checks. Besides each case's checks, watch for anything a user would consider wrong, on every screen you pass through:

- a crash, the app closing or restarting, a frozen screen;
- an error alert or dialog of any kind ("View crashed", "Error", "Unexpected error", "Connection error", an error code or exception text);
- an action that takes over 30 s, or a spinner that never ends;
- text cut off, overlapping, garbled, untranslated or showing a raw key (such as `chat_item_…`), wrong plurals, empty labels;
- a control that does nothing, a duplicated or missing item, an item in the wrong place or order;
- a state that differs after a restart or after switching profile;
- anything that differs from how the row or the step describes it.

Record each in `report.md` under a heading `## Unusual`, with the case it happened in and the screenshot names, even when every check passes. A case passes only when its checks pass and nothing unusual happened in it; otherwise mark it FAIL and say why. Never stop at a failure: go on with the next case.


The app as the scripted smoke test leaves it: the profile "citester" (use the name the user picker shows), without conversations, in the one-hand UI. The test backend runs (see "The test backend" and "Test directory" in this prompt). The cases run in the order of the table and build on each other. Case IDs are `R<row>` of the manual checklist; `S<n>` is a setup step.

## Setup and conventions

- **Shot names** take only letters, digits, `-` and `_`: write a case ID with `-` for the dot (`ui shot R1-10-reachable`).
- **Camera:** if iOS asks for camera access when "Scan / Paste link" or "Connect via link or QR code" opens, tap "Don’t Allow" (`ui point` / `ui tap-xy` if the alert is not in the tree); pasting does not need the camera.
- Use only the test backend's entries and names, the profiles these cases create, and the app's preset servers. Never open, connect to or message "Ask SimpleX Team" or any other preset contact, group or channel, and never search or join anything in the real SimpleX directory: they reach real people.
- Each case uses the entry named for it: cibobby.testing (the contact Robert) in R4.3 and R4.7, cinews.testing (the channel cinews) in R4.4, cinone.testing (not registered) in R4.5, ci_group (found with `ci seed`) in R60.1.
- **New chat** is "Compose": it has "Create 1-time link", "Scan / Paste link", "Create group", "Create public channel" and the search field "Search or paste SimpleX link". Typing a name of 5 or more letters into a search field (the chat list's or the one in "New chat") shows a row "Connect to <name>.testing" (or "Connect to #<name>.testing" for `#name`); tapping it resolves the name online. The keyboard may capitalize the typed name, so the row may read "Connect to Cibobby.testing": find it with `ui find "Connect to"` and tap it with `ui tap-xy` (resolving ignores case). Type a name with `#` quoted: `ui type "#cinews"`.
- **User picker:** your profile image in the toolbar (`Image "Account"`, tap its centre with `ui tap-xy`). It shows the profiles by name in a row at the top (tap another name to switch to it), "Your chat profiles" and "Settings".
- **Adding a profile:** picker → "Your chat profiles" → "Add profile" → `ui tap-value "Enter your name…"`, type the name, check the value, tap "Create profile". If the alert "Make profile private!" shows, tap "Ok". The new profile becomes the active one; close "Your chat profiles" by swiping it down.
- **Sending a message:** tap the message field, `ui type "<text>"`, tap the send button at the right end of the field (its label contains "arrow").
- **Chat info:** tap the chat's name at the top of the chat (`ui find <name>`, the element with the smallest y).
